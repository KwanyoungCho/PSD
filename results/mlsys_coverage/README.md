## Dataset and measurement rules

- `questions.json`: 480 questions copied from the existing repository's tree-AL experiment corpus. Six groups of 80; chat group has eight categories of ten each. The original objects contain 560 turns, but this runner uses **first turns only: 480 inputs**.
- “Full” in this folder means all 480 available first-turn inputs, **not all source datasets or all 560 turns**.
- Initial validation: 16 evenly spaced questions, maximum 48 output tokens, input cap 512, B=1,2,3,4,8, T=0/0.7. Two of the 16 inputs were truncated at 512 tokens.
- Screening: 48 evenly spaced questions, maximum 96 output tokens, B=8, T=0.7. Used for configuration selection, not final statistical claims.
- Every raw run records tokenized inputs, selected question indexes, actual output tokens, truncation count, environment, git revision/diff hash, dtype, metrics, and full token IDs.
- Natural EOS is enabled unless `--ignore-eos` is explicitly recorded. TPS uses actual emitted tokens. Decode TPS and end-to-end TPS are separate.
- Earlier engine counters included speculative tokens discarded after EOS/output caps. All final analyses recalculate speculative TPS from actual returned tokens; AR excludes its prefill token. The engine now counts actual scheduler updates too.
- Final main comparison: all 480 first-turn inputs, input cap 512/output cap 64, B=8/T=0.7, three fresh-process seeds. Greedy full-corpus comparisons and paired K=4/6 repetitions are separate.
- `--seeds` resets target RNG only. Independent seed repetitions use a **fresh process** and `SSD_SEED` for the draft, as the campaign runner does.
- `mlsys_campaign.py` runs jobs sequentially on the same GPU pair and records GPU clocks, memory, utilization and foreign processes every two seconds. GPU isolation does not imply complete host isolation.
- Profiler-enabled runs are for attribution; never substitute their TPS for ordinary throughput runs. Nested profiler spans cannot be added as independent costs.
- Initial `llama3_optimized.json` shares GPU 0 with an unrelated process that began during the run; **exclude its throughput**. Its exact token outputs can still be used for functional checks.

## Implemented corrections and optimizations

| Change | Why needed | Verification |
|---|---|---|
| Ragged greedy recovery uses clamped real accepted length | Padding could select recovery after a token that was never a real proposal | CPU/GPU, pure/mixed temperature regressions |
| Cached prefill uses page table and per-sequence lengths | Flattening physical KV pages corrupted outputs when any prefix was cached | Mixed cached/uncached, noncontiguous pages, fp16/bf16 reference attention |
| Fully cached block-aligned prompts retain one query | Last-token logits otherwise came from an empty query | Block-boundary regression |
| Admission respects `max_num_seqs` | All waiting prompts could be admitted despite requested B | Scheduler regression |
| AMD draft adopts target runtime dtype | Float32 checkpoint bypassed intended cast and failed FlashAttention | Dense model inference |
| Token wire uses 32 token bits | 15-bit token field could not represent Llama3 IDs | High-ID packing tests and actual Llama3 P2 tree execution |
| Non-DUET tree flag is disabled | Default P2 switch enlarged ordinary SSD wire and crashed glue input | Config contract test and SSD reruns |
| One batched verification result transfer; CPU greedy hint | Repeated device readbacks and per-row synchronization | Exact reference parity |
| Batched proxy CUDA Graph | Paper implementation captured proxy ranking only for B=1 | Production eager-policy parity; B=2,3,4,8, ragged rows and changing active B |
| Batched exit-replica support | B>1 gate prevented paper overlap path from running | End-to-end model execution; benefit must be measured separately for TP=1 |
| Unique shared-memory names and scoped cleanup | Concurrent jobs could unlink each other's IPC resources | Separate GPU-pair validation runs |
| All-stochastic JIT fast verifier | GPU→CPU branches and unused greedy work exposed host overhead | Same RNG/cast-order parity and 40,000-sample distribution check; 2,880 real full-corpus sequences identical |
| Greedy-only sampler | T=0 still ran softmax and RNG | Dedicated captured argmax, reject nonzero temperatures; 960 full-corpus outputs identical |
| Preserve original prompt boundary | Re-prefill could drop generated output and reset remaining budget | Budget unit checks and real GPU memory-pressure runs |
| Hash completed block at its own physical page | Crossing a block boundary could register another page's KV as this prefix | Regression fails old code; long-pressure HF next-token audit |
| Count actual committed output | EOS/caps made accepted-token TPS too high | Output accounting regressions and raw-token recomputation |
| Colocated target/draft RMSNorm constants | Different epsilon values triggered Dynamo scalar generalization during capture | Two-epsilon GPU regression and dense synchronous SD runs |

The proxy graph preserves the existing scoring policy; it does not claim better root prediction. Exit-replica was motivated by TP collectives in the original deployment; TP=1 has no such collective to remove, so a speedup here is not guaranteed.

## Correctness evidence and limits

- Initial valid dense-chain sweep completed all 20 model/B/T cells (10 per pair).
- Target AR vs DUET greedy exact sequences: **78/80 Llama2**, **75/80 Llama3** across 16 prompts × five batch sizes.
- Independent HF native-dtype evaluation at the first divergent prefix puts both alternatives in the top two (including ties). Llama2 logit gap 0.015625; Llama3 gaps 0, 0.0625, 0.125. Files: `llama*_greedy_audit.json`.
- This diagnoses near-tie sensitivity; **it does not establish bitwise AR parity or justify claiming zero mismatch**. AR itself varies with B. Further numerical consistency work remains if exact same-token reproducibility is the requirement.
- P2 tree B=1, T=0.7, G=M=4 executed on both full model pairs. Llama2: 150 tree verify events and 398 captured executor replays; Llama3: 79 events and 292 replays. These are execution checks, not tuned tree-vs-chain conclusions.
- Final relevant consolidated regression suite: **184 tests pass**, including CPU/GPU checks. See `run_regressions.sh` and `regression_184.log`.
- Final long memory-pressure run: 76 preemptions (58 after generation began), all 7,680 requested output tokens retained. Independent HF audit at 24 distinct resumed prefixes: every selected token has the maximum logit, max gap 0.
- K1=4→6 changes target kernel shapes and produces 26/480 greedy sequence differences. Both candidates are in HF top-2 at each first divergence, max gap 0.015625. Keep this limitation separate from exact output parity of same-parameter optimizations.

## Reproduction tools

From this worktree root:

```bash
PY=/home/chokwans99/PSD/ssd/.venv/bin/python
$PY ssd/bench/mlsys_campaign.py \
  --plan results/mlsys_coverage/screen_plan.json \
  --directory results/mlsys_coverage/my_screen \
  --gpus 2,3 --port 24600
```

- `ssd/bench/mlsys_coverage.py`: one fresh engine, full raw metrics and token outputs; refuses overwriting an existing output.
- `ssd/bench/mlsys_campaign.py`: sequential fresh-process experiments, logs, telemetry and completion manifest. Choose idle GPUs and unused ports.
- `ssd/bench/mlsys_greedy_audit.py`: independently inspect first AR/DUET divergences with HF logits.
- `ssd/bench/mlsys_verify_bench.py`: verifier-only microbenchmark; not end-to-end speedup.
- `ssd/bench/mlsys_summarize.py`: regenerate throughput, padding, mixed-batch and profile summaries.
- `ssd/bench/mlsys_preemption_audit.py`: HF audit of snapshots from `--audit-preemption`; snapshots are for correctness runs, not throughput measurements.
- Defaults enable `SSD_FAST_VERIFY=1` and `SSD_BATCHED_PROXY_GRAPH=1`; setting both to zero reproduces the corrected timing baseline. Mixed-temperature/non-JIT verification retains the general path.
- `--greedy-only` configures the engine before graph capture and requires T=0 for both target and draft requests. Omitting it preserves mixed-temperature support.
- TP=1 measurements use `SSD_DUET_EXIT_REPLICA=0`; do not generalize that setting to TP>1 without measuring.

The original paper's external `baseline/runners/run_duet.py`, `baseline/data/specbench_full.jsonl`, and `DUET_PAPER_RESULTS/scripts/` are not present on this server. This harness validates and compares the exact paper engine source, but cannot be labeled a byte-for-byte reproduction of that external experiment driver.
