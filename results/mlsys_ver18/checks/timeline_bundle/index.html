모델마다 PDF 하나입니다. 각 페이지는 같은 요청의 연속 두 step이며 P1 hit / P2 hit / miss를 구분합니다. 같은 모델의 여러 설정은 같은 PDF 안에서 구분합니다.

빨간 점선: 다음 target 요청 시작(deadline 기준). 초록 원: PS cache 완성. 삼각형: draft 수신 준비. 흰 점선은 forward 횟수 표시이며 실측 개별 forward 경계가 아닙니다. 양수 여유 시간이 모두 추가 계산 예산이라는 뜻은 아닙니다.

표는 P1 hit·P2 hit·Miss·Overall(전체 평균)의 네 행입니다. 그림 위의 두 step은 실제 예시이고, 표는 해당 설정의 유효 진단 구간에 대한 문항 평균입니다. Step: 현재 target 요청 시작→다음 요청 시작. DS/PS total: 준비·정리 포함 phase 시간. DS spare*: proxy 전송 준비 완료−DS 완료(수신 도착 시점은 아님). PS spare: 다음 target 요청 시작−draft 수신 준비. 양수는 여유, 음수는 초과입니다. Graph/K1·K2는 graph 시간을 forward 횟수로 나눈 값이며 sampling·tree 선택을 포함합니다.

분류는 현재 step에서 사용한 cache 기준입니다. 전체 평균은 요청별 지표를 문항 내에서 평균한 뒤 문항 간 동일 비중으로 평균합니다. n은 관측 step 수입니다. 표본이 없으면 0 대신 N/A입니다.

Rate는 P1/P2 hit·miss의 발생 비율이며, Overall 행에서는 전체 cache hit rate를 표시합니다. AL은 recovery/bonus를 포함한 수락 길이입니다. Profile TPS는 요청별 유효 진단 구간의 반환 토큰 수÷시간을 구한 뒤 문항 평균한 값으로, profile OFF 또는 전체 데이터셋 TPS와 구분합니다. 토큰 수 기록이 없으면 AL/TPS를 추정하지 않고 N/A로 표시합니다.

Proxy 계산과 target 후반 forward의 중첩 여부는 설정별로 기록에서 계산합니다. exit_proxy_side라는 이름만으로 별도 stream 실행을 뜻하지 않습니다. 전송은 비동기 enqueue만 기록되어 실제 통신 완료·중첩 시간은 알 수 없습니다. Target와 별도 draft GPU의 병렬 실행과는 별개입니다.

기존 raw 기록의 후처리입니다. 측정 버전·환경은 모델별 설명을 확인하세요. 다른 서버/설정의 절대 시간을 직접 비교하여 개선으로 해석하지 않습니다.
